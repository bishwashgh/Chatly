# Deploying Chatly on Render (3 services)

- `chatly-api` — NestJS GraphQL backend (web service)
- `chatly-postgres` — PostgreSQL (free plan)
- `chatly-redis` — Key Value / Redis, used for GraphQL subscriptions pub/sub

The mobile app is **not** deployed to Render — it's an Expo/React Native app.
You just point it at the deployed API (see bottom).

## 1. One-click via Blueprint (recommended)

1. Push this repo to GitHub.
2. Render Dashboard → **New +** → **Blueprint** → select the repo.
   Render reads `chatly_backend/render.yaml` and creates all 3 services,
   wiring `DATABASE_URL` and `REDIS_URL` automatically.
3. First deploy may fail — that's expected if secrets are missing (step 4).
4. On `chatly-api` → **Environment**, add:
   - `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` — auto-generated by the blueprint
   - `GOOGLE_CLIENT_ID` — Google OAuth client ID
   - `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `LIVEKIT_URL` — LiveKit cloud
   - `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`
5. **Manual Deploy → Deploy latest commit** to restart with the new vars.

## 2. Manual setup (no blueprint)

| Service | Type | Settings |
|---|---|---|
| `chatly-postgres` | PostgreSQL | free plan, region of your choice |
| `chatly-redis` | Key Value | free plan |
| `chatly-api` | Web Service | root dir `chatly_backend`, Node runtime |

`chatly-api` commands:

- Build: `npm ci && npx prisma generate && npm run build`
- Pre-deploy: `npx prisma migrate deploy` (runs pending migrations against Render Postgres; on a db-push era DB the startup script baselines first)
- Start: `node dist/src/main.js`
- Health check path: `/graphql`

Environment variables: `NODE_ENV=production`, plus copy the
**Internal Database URL** from the Postgres service into `DATABASE_URL`,
and the **Internal Connection String** from the Key Value service into
`REDIS_URL`, then the secrets listed above.

## 3. Important settings

- **WebSockets**: the app uses GraphQL subscriptions (`graphql-ws`).
  Dashboard → `chatly-api` → Settings → **WebSockets → ON**.
- **CORS**: `main.ts` currently allows `origin: '*'`. Fine to start; tighten it
  later to your own origins.
- **Schema sync**: the repo ships an initial migration in
  `prisma/migrations/001_initial/`. Because the Render Postgres may already
  have tables (created by a previous `db push` deploy) but no
  `prisma_migrations` tracking table, the startup runs
  `prisma/migrations/bootstrap.sh` first. This script:

  1. Detects a non-empty schema without a `prisma_migrations` table
     (a database from the `db push` era).
  2. Baselines it with `npx prisma migrate resolve --applied 001_initial` —
     Prisma itself records the migration as applied (with the correct
     checksum). Safe: no data is dropped.
  3. Runs `npx prisma migrate deploy` to apply any **new** migrations.

  This means the first deploy with this setup adopts the existing database
  using Prisma's supported baseline flow. After that, every deploy just
  runs `migrate deploy` normally.

  When you change `schema.prisma`, generate a new migration locally with
  `npx prisma migrate dev` (or write it manually), commit the new folder
  under `prisma/migrations/`, and Render will apply it on the next deploy.

## 4. Point the mobile app at Render

The mobile app reads env vars at build time (Expo), not runtime:

1. In `chatly-mobile/.env` set:
   - `EXPO_PUBLIC_API_HTTP_URL=https://chatly-api.onrender.com/graphql`
   - `EXPO_PUBLIC_API_WS_URL=wss://chatly-api.onrender.com/graphql`
   - Google / LiveKit values as usual
2. Rebuild/restart the Expo dev server (or rebuild the native app).

## 5. Free-plan caveats

- API sleeps after ~15 min idle → first request is slow; WebSocket
  subscriptions drop while asleep.
- Free Postgres expires after 30 days — upgrade or back up before then.
- The startup runs `prisma/migrations/bootstrap.sh` on every deploy.
  On the first deploy it baselines a pre-existing (db-push era) database
  with `prisma migrate resolve --applied 001_initial` (safe — no data
  dropped). On subsequent deploys it's a no-op and only
  `prisma migrate deploy` runs.
